# Frostpunk reverse-engineering lab

Цель первого этапа — восстановить путь изменения одного ресурса (начнём с угля):

```text
значение в интерфейсе
  -> адрес в памяти
  -> инструкция, которая пишет по адресу
  -> объект-владелец ресурса
  -> функция изменения ресурса
```

Мы не изменяем файлы игры, не обходим DRM и не распространяем код или данные игры.
Все заметки и сигнатуры привязываются к конкретному SHA-256 `Frostpunk.exe`.

## После завершения загрузки

1. Запустить игру обычным способом, дойти до главного меню и закрыть её.
2. В PowerShell из этой папки выполнить:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\Collect-FrostpunkBuild.ps1
   ```

   Если автоопределение не сработало:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\Collect-FrostpunkBuild.ps1 -GamePath 'D:\Steam\steamapps\common\Frostpunk'
   ```

3. Скрипт создаст `artifacts/build-<короткий SHA>/inventory.json` и не будет
   модифицировать установку игры.

## Первая динамическая сессия

Используем отдельное тестовое сохранение. Запоминаем точное видимое количество угля,
ищем это число как 4-байтовое целое, тратим или получаем уголь и фильтруем результаты.
Когда останется несколько адресов, ставим аппаратную точку останова на запись и
фиксируем инструкцию, стек вызовов и базовый адрес модуля. Простая подмена числа —
только способ найти код; итоговая цель — понять функцию и структуру данных.

Шаблон журнала находится в `notes/session-template.md`.

Текущие восстановленные смещения и структура экономики записаны в
`notes/recovered-economy-api.md`.

## Собственный сканер и отладчик памяти

По умолчанию команды `scan`, `next` и `list` только читают память процесса.
Команды `watch`, `override-r8` и `set-coal` подключаются как отладчик, а последние
две могут изменять регистры игрового потока. Используйте отдельное сохранение.

Сборка:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Build-FrostProbe.ps1
```

Первый поиск после загрузки города (пример: на экране ровно `123` угля):

```powershell
.\bin\FrostProbe.exe scan --process Frostpunk.exe --value 123 --state .\artifacts\coal.scan
```

После того как количество угля изменилось, но игра не перезапускалась:

```powershell
.\bin\FrostProbe.exe next --state .\artifacts\coal.scan --value 117
```

Повторяем изменение и `next`, пока кандидатов не останется мало. Файл состояния
привязан к конкретному запущенному процессу; после перезапуска игры нужен новый `scan`.

## Подтверждённый эксперимент

Для GOG-сборки с SHA-256
`719c6e016bcdb1021a6401b1624aebdcfb03c6782a763d2fbd8c2805f9dae9d4`
восстановлена функция `FrostpunkEconomy::ChangeResource` по RVA `0x168E340`.
Аппаратная точка останова поймала естественный расход угля `-1`; FrostProbe один
раз заменил аргумент функции на `+159`, после чего игра штатно изменила уголь
с `41` до `200` и обновила интерфейс.

После самостоятельного повторения поиска и только для указанной сборки:

```powershell
.\bin\FrostProbe.exe set-coal --state .\artifacts\coal.scan --target 200
```

Нужно снять паузу, чтобы игра естественным образом вызвала функцию расхода угля.
Абсолютные адреса не переносятся между запусками из-за ASLR; инструмент использует
RVA для кода и заново получает адрес объекта экономики.

Проект не содержит бинарников или ресурсов Frostpunk и не предназначен для обхода
DRM, сетевых ограничений или античита.
